# 任务定义与技术路线

## 任务一

左臂到抓杯位，调整拇指与其他手指闭合，抓取后下移并转移至双臂交接区域；右手握杯，左手松开并撤离，右手撤退、放置、松手。任务结束后可经保持使能的回位流程返回初始姿态。

### A：调好的分段示范轨迹

入口 `task1_tuned_full.sh`。冻结流程共14段：reach、approach-hand、thumb、fingers、extract、left-align、right-align、right-grip、left_open_handover、left_clear_handover、right_retreat_handover、right_place_handover、right-release-angle、right_open_handover_table。

组合入口请求3倍任务速度、4倍回位速度。受各段约束影响，这不意味着每段实测速率严格乘相应倍率。历史一次打印的任务规划时间约85.3秒，不含确认与回位，不能作为重复实验平均值。

该路线的主要贡献是示范轨迹调节、抓取/交接手型、阶段衔接与稳定执行基线，而非网络训练。

### B：状态历史、实测进度与CNN

入口 `task1_nogoal.sh run --execute --full`。保留8步26维状态历史、当前顶视深度输入与局部实测匹配得到的标量进度。后续修订加入分别学习的进度手臂头和手部头，缓解在抓取阶段到位却不闭合的问题。

当前保存版加入任务一专用局部进度恢复：实测姿态越过小搜索窗口时，可在有限邻域重新推进，且不跨越超过允许变化的手型段。该修改已用卡住日志离线验证，未据此宣称完成新的硬件全程测试。

## 任务二

右手从桌面抓杯，移向封口设备，执行封口相关阶段，然后再次抓取封口后的杯子、移出并放置。应单独评价封口操作轨迹完成与实际封口质量。

### A：目标条件模型与教师参考控制

入口 `task2_fixed.sh run --execute --full`。模型为v24，训练源自v23及教师执行记录的离线重标注。参考阶段目标与纠正机制是部署的一部分。记录中部分试验含大量 `teacher_cycles`，必须披露控制来源。

当前封口后抓杯及持杯相关段的右手食指205、小指210 raw；从桌面首次抓杯沿用该A路线原设置。不要把B路线首次抓杯手型自动归到A路线。

### B：学习阶段、标量进度动作头与CNN

入口 `task2_nogoal.sh run --execute --full`。阶段网络从状态历史预测阶段概率，并参与基础动作预测；最终部署动作主要来自标量进度动作头，叠加有界的状态/视觉动作修正。

保存版中的运行时手型：首次桌面抓杯食指205、小指220；封口后再次抓杯食指205、小指210 raw。首次食指从训练头214改到205，是运行时平滑覆盖，原权重未改变。数值为灵巧手raw单位，不是角度。

## 组合执行与完成判定

`task12_routes.sh` 支持模式1、2、12和任务分别选择A/B：完成任务 → 验证停止/保持状态 → 空载回位 → 下一任务。人工完成入口 `task12_finish.sh` 的确认是“操作者声明本任务结束”，不等于自动视觉成功检测。

自动完成包含终点进度、实测终点误差、稳定停留及owner状态检查。人工声明与自动完成应在实验表中分别记录；恢复初始位是独立阶段，不属于抓取成功判据。
