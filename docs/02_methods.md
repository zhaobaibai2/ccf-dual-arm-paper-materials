# 网络、进度估计和控制执行

## 状态与视觉表示

状态顺序为：左臂7维弧度、右臂7维弧度、左手6维raw、右手6维raw，共26维。B路线状态历史为8步，标称采样间隔0.05秒。归一化使用训练检查点中保存的center和scale。

任务一输入接口为 `images[8,1,2,60,80]`，任务二为 `images[8,1,2,120,160]`；当前网络调用取最近顶视图。两个图像通道是深度预处理表示，不是RGB双通道。具体预处理语义应以源代码和数据契约为准。

网络预测16步26维动作块。标称动作网格0.05秒，预测范围约0.8秒。策略请求频率10Hz，底层控制周期约0.01秒；这些为配置值，实际频率需从时间戳统计。

## 任务一网络

基础 `ProgressPolicy` 将208维状态历史与1维标量进度拼接，经384、384、256维SiLU MLP输出手臂、手部和事件头。CNN分支由两层卷积、SiLU、自适应池化及线性层组成，产生有界手臂残差。

当前transition v4还加载进度动作头：手臂主预测由进度手臂头产生，基础状态/视觉预测相对当前状态的修正限制在±0.005 rad；手部由进度手部头输出。因此不能仅用基础网络示意图描述最终部署。

## 任务二网络

`PhasePolicy`：8步状态历史 → 384、384、256维MLP → 阶段logits；阶段softmax经64维映射与256维特征拼接，生成动作与事件。顶视CNN补充有界手臂残差。

部署适配器再使用 `ProgressHand(channels=26)` 输出动作主项，叠加基础网络动作与当前状态之差的±0.005 rad手臂修正。阶段概率仍可记录，但最终动作不能称为纯阶段网络直接输出。

进度动作头以标量进度及傅里叶特征为输入，输出完整动作块；准确结构见 `reference_code/progress_hand.py`。

## 标量进度的估计

记示范状态序列为 q̄_i，实测状态为 q_t，当前索引为k，活动维度集合为M。采用归一化最大误差：

`e(i,t) = max_{j∈M} |q̄[i,j] − q[t,j]| / r[j]`

基础匹配范围为k到k+4；取满足e≤1的最远索引，得到 `p=k/(N−1)`。通常手臂半径0.03 rad、手部8 raw；任务二指定抓取区间的食指匹配半径使用12 raw。进度匹配阈值与底层控制误差阈值不能混为一谈。

这不是按时间强行推进。网络只接收标量进度而非goal26，但估计器依赖示范状态序列，需在论文明确报告。

## 有限邻域恢复

基础匹配不推进时，在当前到后续25个点内找满足原误差范围的近邻，每次最多推进4个点。手型变化超过2 raw时拒绝恢复；任务一实现检查所有手通道，任务二既有实现检查活动手通道。恢复不能代替抓取或开手动作。

实际案例：任务一B曾停在索引1902约198秒，左臂第7关节已更接近后续轨迹。检查当前后4点时误差仍约0.039～0.053 rad，大于0.03阈值。离线使用该实测姿态，恢复后索引依次1906、1910、1914、1918、1922、1925。此为局部逻辑验证，不是接触物理仿真或实机成功率。

## 连续控制和反馈

链路：相机与实测状态 → 网络动作块 → 连续轨迹拟合/拼接 → 速度等限制 → 唯一owner下发 → 反馈与日志。

现有chunk参数包括commit_s=0.04、bridge_s=0.1、spline_strength=0.03、spline_controls=8、min_tail_s=0.08。最终发送参考与原始模型预测分别记录，不能用网络预测代替实际动作。

owner处理租约、反馈有效性、动作跟踪和停止。曾有针对任务一右手交接食指的限时迟滞等待：30 raw仅是限定阶段等待上限，并非所有手指全局容忍值，也不表示增加抓取力。

## 完成条件与局限

进度到末尾、实测终点在范围内并稳定约0.5秒后，适配器可输出完成事件；执行层再判断保持条件。物体是否抓稳、是否正确放置、是否封口合格，不能仅由这些位置条件推断。

状态主导、显式进度及有界视觉残差适合当前重复场景，但视觉贡献、场景变化适应性与独立泛化尚需消融和独立测试。
